## M5a security implementation corrections (2026-10-28)

- D15's intended bcrypt length boundary is enforced as **72 UTF-8 bytes**, with NUL rejected before hashing,
  for registration/reset/admin creation. Minimum length, letters/numbers, login compatibility and existing
  accounts are unchanged; no pending authentication/product decision was resolved.
- D6a now validates the URL-resolved driver/host/port/schema before database traits; e2e verifies the live
  isolated MariaDB 11.4 server before preparation. Test targets are pinned to loopback port 3307 without
  changing credentials. Read/write overrides and Unix sockets are refused.
- A5 private photo responses now use `private, no-store`; login/registration also clear the previous identity's
  query caches and cancel requests, as logout already did. These are privacy fixes, with no workflow redesign.
- Existing admin audit price visibility needs an explicit decision against the buyer-only quote wording;
  current behavior is preserved. Evidence and regression outcomes: [`SECURITY_M5A.md`](reports/SECURITY_M5A.md).

## M5b accessibility implementation notes (2026-10-28)

- Keep the existing RTL design tokens and inline confirmation model. Buyer/supplier confirmations now use
  a named native fieldset with question focus, Escape while idle, and trigger return on cancellation; Tab
  stays in normal document order. No state transition or approval/contact decision changed.
- SPA task titles/main focus exclude private record content and URL query parameters. Narrow header/name
  and long-price typography fixes preserve the original components, currency formatting and calculations.
- Forced-colour focus/native select support and existing error-summary patterns were extended; Arabic
  triage conflict copy was repaired. Evidence and limits: [`ACCESSIBILITY_M5B.md`](reports/ACCESSIBILITY_M5B.md).
- Admin audit quote-price visibility remains explicitly pending from M5a; no product decision was resolved.

## M5c performance and reliability implementation notes (2026-10-28)

- D34's seen-quote requirement retains the same API field and row-lock order. Quote timestamps now preserve
  microseconds end to end, with monotonic model-generated versions for an equal/backward clock. Clients echo
  the exact ISO value. Legacy whole-second records remain valid; no selection/product decision changed.
- Expiry keeps its conditional state transition and 200-row chunks. Each transition/audit is atomic; a failed
  audit leaves that RFQ retryable. D39 still sends nothing for expiry. A measured `(status, closes_at, id)`
  index reduces actual rows examined from 10,010 to 10 in the synthetic MariaDB fixture.
- Both new migrations were authored and tested only on `warridli_test:3307`; application to development
  requires separate approval. Timestamp downgrade discards fractions and must not be run casually.
- Page code splitting uses React lazy/Suspense inside the persistent RTL layout to preserve keyboard focus,
  with a generic Arabic chunk-failure/reload path. No new dependency, cache infrastructure or queue.
- Existing pagination, global quote comparison, metrics definitions, matching, notification audience/policy
  and admin audit price visibility stay unchanged. Evidence and scaling limits: [`PERFORMANCE_M5C.md`](reports/PERFORMANCE_M5C.md).
